Zustände des Blitzes

🪟 Windows Inferenz läuft — Modell verarbeitet gerade Tokens 🪟 Windows Modell geladen, Server idle 🐧 Ubuntu Watch eingerichtet, API nicht erreichbar 🍏 macOS kein Blitz — Gerät ohne Watch oder Host offline
Erkennung auf bestehenden Feldern (ohne Protokoll-Änderung):
  • model_metrics.total_tokens ist der einzige Wert, den der Host frisch liefert (nicht gelatcht). Delta zwischen zwei Polls > 0 ⇒ Job läuft. Gilt für llama.cpp (prompt_tokens_total + n_decode_total) und Strata (totals.prompt_tokens + output_tokens).
  • prompt_tps/predicted_tps sind unbrauchbar: der Host hält den letzten Nicht-Null-Wert fest (_MODEL_TPS_CACHE), ein idle Server meldet weiter seine alte Rate.
  • Die Dashboard-Heuristik INFERENCE_GPU_PCT (GPU ≥ 60 % an zwei Polls) funktioniert nur für die ganze Maschine und versagt bei CPU-/RAM-Inferenz (--cpu-moe, PLE-Offload).
  • Sauberer Fix = Protokoll v9: requests_active aus llamacpp:requests_processing bzw. Strata live.state/live.queued — dann kein Delta-Cache und kein Fehlalarm beim Counter-Reset (Server-Neustart).
Intervall: bewusst ein eigener Wert (Default 10 s, Wahl 5/10/15/30 s), nicht das Dashboard-Dropdown (2/3/5/10 s). Auf N Kacheln pollt man N Geräte gleichzeitig, und jeder Watch-Eintrag löst pro Poll HTTP-Calls aus — ein Server mit 43 gemeldeten Modellen bedeutet 43 /metrics-Requests je Poll. Unter 2 s bringt nichts, weil der Host GPU mit 1,5 s und die API-Identität mit 10 s TTL cacht. Delta-Erkennung braucht zwei Polls ⇒ Anzeige dauert maximal 2 × Intervall.
